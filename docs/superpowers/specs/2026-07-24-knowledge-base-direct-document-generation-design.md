# 知识库直连文档生成设计

## 背景与目标

文档生成页面目前要求用户先拥有可访问的项目、已批准基线和项目来源快照。实际测试与日常使用中，用户已经通过知识库授权获得可检索的数据，但没有项目管理入口来完成这些前置条件，导致无法创建生成任务。

本设计将新建文档生成任务改为直接选择当前登录用户有读取权限的知识库。项目型历史任务和后端兼容接口保留，但新页面流程不要求创建、选择或管理项目。

## 用户流程

1. 用户登录并进入“文档生成”。
2. 在“新建生成任务”中，从“已授权知识库”列表自行选择一个知识库。
3. 选择已启用的安全模板和与其版本匹配的已批准 Document Schema。
4. 创建生成任务，或选择自动生成并发布。
5. 页面持续显示 Harness 的检索、撰写、校验、渲染和审批进度；用户可下载候选文件或批准发布。

模板上传、OOXML 活动内容净化、模板确认、候选文件校验和人工审批的既有流程不变。

## 方案选择

采用直接知识库作用域方案，而非为知识库自动创建隐藏项目，也不使用仅保存在浏览器会话中的临时输入。每个任务会持久化创建人、租户、知识库名称以及创建时的检索范围快照，使任务能持续显示状态并可审计。

## 架构与数据流

### 任务作用域

新增知识库作用域的工作单入口。创建工作单时，服务层必须：

- 通过现有权限服务确认当前请求上下文对所选知识库拥有读取权限；
- 保存知识库名称、租户和创建者作为任务作用域；
- 记录创建时可枚举的知识库文档标识或等价的来源快照；若后端无法提供稳定文档版本，则至少保存知识库名称和创建时间，并在每次运行前重新校验访问权限；
- 不接受前端直接传入任意本地路径、未授权知识库名称或聊天上下文。

现有项目型工作单继续以项目来源快照运行，不进行数据迁移或删除。读取状态、控制 Harness、下载产物和审批时按工作单作用域分别执行项目权限或知识库权限校验。

### 检索与生成

知识库作用域工作单的检索器只查询其保存的知识库；每条被采纳的证据继续写入任务的证据、验证和运行记录。自动生成仍仅在检索、撰写、校验和渲染均通过时发布；证据不足、权限失效或安全校验失败时，保留候选文件并进入人工处理或阻塞状态。

### 页面

“新建生成任务”和“任务与下载”不再显示项目选择器。前者显示已授权知识库下拉框；后者显示当前用户在其可访问知识库范围内的工作单，并可按知识库筛选。没有可读知识库时，页面明确提示用户联系管理员授权知识库。

页面使用服务层返回的安全摘要，不显示原始 OOXML 部件、上传文件字节或模型密钥。上传模板仍与知识库选择解耦，用户可先完成模板分析和启用。

## 错误处理

- 未登录或无知识库读取权限：拒绝创建，并显示可操作提示。
- 知识库在任务创建后被撤权：拒绝后续运行、状态读取、下载和审批。
- 所选知识库没有可检索资料或检索证据不足：创建或运行阶段给出明确状态，不发布最终文件。
- 模板或 Schema 未确认、已失效或不匹配：阻止创建任务。
- 旧项目工作单：继续按原项目权限模型读取和运行，避免影响已存在记录。

## 测试与验收

- 页面只列出当前用户可读取的知识库，并支持用户自行选择。
- 不存在项目或基线时，使用已授权知识库仍可创建并运行任务。
- 未授权知识库、伪造知识库名称和撤权后的访问全部被拒绝。
- 生成检索仅调用被选知识库，并记录证据与任务作用域。
- 模板净化、Schema 匹配、Harness 进度、候选审批和下载的现有回归测试继续通过。
- 既有项目型工作单的创建、状态和下载接口保持兼容。

## 非目标

- 本次不新增项目管理页面，也不迁移或删除既有项目数据。
- 本次不放宽模板安全净化规则，不允许宏、外链、OLE/Visio 或控件进入生成产物。
- 本次不将聊天会话、浏览器会话或任意本地文件作为生成来源。
