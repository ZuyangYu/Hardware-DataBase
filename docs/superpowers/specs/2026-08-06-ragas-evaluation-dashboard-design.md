# RAGAS 评估仪表盘优化设计

## 目标

将 5175 端口的 React RAGAS 评估页面升级为“总览优先”的评估仪表盘，使系统管理员能先判断一次运行的结果是否可信、是否通过门禁，再查看指标趋势与可定位的问题样本。

## 背景

当前 React 页面已支持创建、控制、列表、摘要和历史数值比较，但摘要只显示指标行，无法表达门禁阈值、评分覆盖和问题样本。`Hardware-DataBase-integrate-develop` 中的 Streamlit 页面已经具备以下展示逻辑：

- 可信度摘要：采集成功、检索证据覆盖、评分覆盖、技术失败和门禁状态；
- 带阈值的当前指标横向柱状图；
- 当前运行与基线运行的分组柱状图；
- 可筛选、可展开的样本诊断。

本设计将这些信息架构与判定规则迁移到 React 页面，不迁移 Streamlit 或引入图表依赖。

## 非目标

- 不改变 RAGAS 打分、门禁阈值或评估运行生命周期。
- 不更改评估结果文件格式。
- 不建设跨多个运行的趋势分析页，也不增加导出功能。
- 不向非系统管理员暴露评估结果、问题或检索上下文。

## 方案选择

采用扩展运行详情接口与页面内原生 SVG/CSS 图表的方案。

- 不采用“纯前端图表”方案，因为样本诊断尚未由 API 提供。
- 不采用新图表库或独立分析页，因为现有指标数量有限，原生组件可满足 0–1 柱状图、阈值刻度与分组比较，且能避免新的包和维护面。

## 信息架构与布局

完成运行的详情面板按以下顺序展示：

1. **运行可信度总览**：运行 ID、运行状态、门禁状态、样本数、采集成功数、有检索证据数、已评分数、评分失败数。
2. **待处理事项**：采集失败、评分失败、关键样本待复核和无检索证据的数量；技术失败或评分覆盖不足时给出解释，避免把分数误读为可靠结论。
3. **当前评估效果**：每个指标一条 0–1 横向柱状图，显示中文名与代码、分数、适用样本数、评分失败数和门禁阈值标记。达标为绿色，未达标为红色，无阈值为中性灰。
4. **指标与门禁**：保留可扫描的指标表与门禁失败原因，作为图表的精确数值补充。
5. **历史对比**：选择基线后，按相同指标绘制“当前/基线”分组柱状图，并保留当前、基线与变化量表格。只比较两次运行均存在的指标。
6. **样本诊断**：状态筛选与紧凑表格；展开行后显示问题、参考答案、实际回答、检索上下文、检索摘要与单样本指标结果。

创建评估和运行列表保持现有功能，视觉令牌沿用当前前端的中性背景、白色卡片和语义色。

## 数据流与接口

`GET /api/v1/evaluation/runs/{run_id}` 在保留现有运行状态与 `summary` 的基础上，增加可选 `sample_results` 数组。服务端从该运行目录的 `results.jsonl` 读取并验证 `SampleResult`，再转换为可 JSON 序列化的响应模型。数组元素至少包含：

- 样本 ID、采集状态、关键样本标记；
- 问题、参考答案、实际回答与检索上下文；
- 检索摘要；
- 指标名称、状态、得分与失败原因。

接口继续使用 `require_system_admin`。只有选中运行时才会读取该文件；运行列表不加载样本结果。已完成但没有 `results.jsonl` 的运行返回空数组；解析失败不影响运行状态与摘要的读取，并以明确的诊断不可用信息反馈给页面。

前端将样本归类为：采集失败、评分失败、关键样本待复核、无检索证据、正常完成。可信度总览从 `summary` 与这些样本结果派生，避免把缺失的评分或技术失败隐藏在平均分之后。

## 图表与可访问性

- 使用可复用的前端图表组件或页面内小组件，基于语义 HTML、CSS 和 SVG 绘制；不增加第三方图表包。
- 所有图表数据均有表格或文本替代；柱状图同时显示数值，不只依赖颜色。
- 分数值限制在 0–1 显示域；缺失分数不绘制为零。
- 指标排序与集成开发版保持一致：完整性、证据一致性、答案正确性、忠实性、答案相关性、上下文精确率、上下文召回率、缺失信息诚实性、冲突披露，未知指标置后。
- 小于 900px 时，总览卡片、图表和诊断表折叠为单列或允许横向滚动，确保不裁切关键数据。

## 错误与空态

- 没有摘要：保持已有运行进度展示，不显示评分图表。
- 没有有效评分指标：显示“暂无可展示的有效评分指标”。
- 没有共同指标：历史对比显示“没有可直接比较的同名指标”。
- 无样本结果：显示“暂无样本诊断数据”，不阻断摘要与对比。
- 样本诊断读取失败：页面显示诊断不可用信息，但继续展示可信度总览中可从摘要得出的数据。

## 验收与测试

- 后端测试覆盖：完成运行返回序列化的样本诊断；缺失结果文件返回空数组；坏的结果文件不会使运行详情接口整体失败；系统管理员访问要求保持不变。
- 前端测试覆盖纯数据函数：指标名称/排序、阈值状态、样本状态归类与可信度统计。
- UI 手工验收：完成运行显示总览、待处理事项、阈值柱状图和门禁原因；选择基线显示分组柱状图；筛选并展开问题样本可查看详细诊断。
- 执行 Python 相关测试与 `npm run build`，确保 API、类型和前端构建兼容。
