# 文档生成优化设计

## 目标

让大多数常规 XLSX/XLSM 模板在不覆盖固定内容、不扩大来源范围且具备字段级证据的前提下，自动生成可直接进入审批的候选文档。DOCX 保持同一字段契约和检索约束，作为兼容路径，不在首期做模板类型专项优化。

## 非目标与硬约束

- 不复用开放式问答 Agent 直接生成文档，也不允许其访问 Work Order 冻结来源以外的知识库内容。
- 不自动覆盖公式、受保护单元、隐藏单元、表头、固定标签或未被明确判定为样例/默认值的非空内容。
- 证据命中不等于字段可填；字段必须通过其值类型、来源和一致性校验。
- 检索失败、字段歧义、来源冲突或低置信度时不猜测，保留空值或规范“待补充”标记，并将 Work Order 转人工处理。

## 现状问题

1. 模板建议按可写单元分块，缺少工作簿级的表格、表头、样例和重复区语义，易把固定内容或布局空格认成字段。
2. `retrieval_terms` 会保存到 `DocumentFieldSchema`，但实际检索查询只拼接字段标签和描述，模板分析的检索词没有生效。
3. 字段检索可调用文本、表格和电路检索器，但缺少字段级来源规划、结果截断、覆盖度判断和基于缺口的补检。
4. Writer 可以从全部返回证据生成文本；当前词法锚点校验只能证明“引用过证据”，不能证明“答案符合字段要求”。
5. 自动激活把 LLM 建议的所有单元列入非空覆盖白名单，并放宽低置信度和布局风险检查，导致“可激活”与“可安全自动填充”脱钩。

## 方案概览

```text
模板文件
  -> 确定性结构分区
  -> 候选填写区
  -> 字段契约（LLM 辅助、规则裁决）
  -> 冻结来源内字段检索计划
  -> 多源检索 / 重排 / 缺口补检
  -> 类型化候选值 + 证据包
  -> 字段级验证
  -> 自动进入审批 | 转人工处理
```

所有中间产物均绑定模板版本、SourceSetSnapshot、HarnessPolicy 和字段契约版本；审批后仍复用候选文件字节，不重新检索或渲染。

## 一、模板拆解与字段契约

### 1. 确定性结构分区

在现有 OOXML 安全分析之上，增加 Workbook 级布局解释器，为每个单元和连续区域给出以下角色：

- `title`、`section_header`、`table_header`、`fixed_label`：绝不自动写入。
- `placeholder`：可自动写入。
- `sample_value`：仅在模型给出明确覆盖理由且规则验证通过时可写入。
- `scalar_input`：单值字段候选。
- `repeating_table_row`：重复表行候选，首期只登记，不自动扩行。
- `layout_blank`、`unknown`：不可自动写入。

分区依据包括合并范围、行列邻域、样式指纹、连续空白区域、表头文本和样例值模式。LLM 接收的是候选区和足够的同表上下文（表标题、表头、左右/上下邻居、区域边界），而不是独立的 50 个单元片段。

### 2. 字段契约

每个可自动生成字段使用稳定 ID，并含：

```json
{
  "field_id": "connector_x1900_pin_1_signal",
  "label": "X1900-1 信号",
  "description": "X1900 接插件第 1 针的网络名和信号用途",
  "subject_aliases": ["X1900-1", "I_S_WKUP"],
  "query_terms": ["X1900 pin 1", "I_S_WKUP", "pin definition"],
  "value_schema": {"kind": "scalar", "value_type": "text"},
  "required_capabilities": ["relationship_lookup"],
  "preferred_source_roles": ["schematic"],
  "fill_policy": "auto_if_verified",
  "overwrite_basis": "placeholder|sample_value",
  "confidence": 0.0
}
```

LLM 只能提出字段契约、样例覆盖理由和置信度；服务端负责验证目标在候选填写区、契约 ID 唯一、值类型受支持、覆盖理由和单元角色一致。只有 `placeholder` 或通过规则验证的 `sample_value` 能进入自动激活；其他单元保留给人工映射。

### 3. 缺少字段描述

没有显式描述时，服务端可从表头、同一行/列标签、区域标题、样例值和已知别名生成“检索描述候选”。候选描述只用于检索规划，不能作为写入文档的事实。上下文不足时契约状态为 `needs_schema`，字段不自动填充。

## 二、字段检索

### 1. 受控借鉴智能问答

复用智能问答的能力路由思想：文本 RAG、表格语义索引和电路索引并行或按能力调用；保留其查询改写、去重、来源角色加权和检索诊断。

不复用开放式问答的全知识库搜索和自由多跳决策。每次检索都必须携带 Work Order 的 `SourceSetSnapshot`，且检索器继续对 source version、处理产物和来源名做双重验证。

### 2. 查询与路由

字段查询按以下优先级构造：

1. 查询改写结果；
2. `subject_aliases + query_terms + description + label`；
3. `label + description`；
4. 仅 `label`。

检索计划依据 `required_capabilities`、`preferred_source_roles` 和 `value_schema` 决定：

- 标量文本：RAGFlow 文本为主，必要时表格索引补充。
- 器件、网络、引脚和连接关系：电路索引优先，文本 RAG 交叉验证。
- 表格字段：表格索引优先，RAGFlow 提供补充上下文。

每个字段设固定 evidence budget（首期最多 5 条去重后证据），并记录各检索器的 query、命中、过滤原因和最终入选理由。

### 3. 缺口补检

只在首轮证据无法满足字段契约时进行一次定向补检：

- 缺少实体别名时，使用 `subject_aliases` 扩展查询；
- 关系字段没有结构化证据时，切换或补充电路索引；
- 表格字段没有可解析值时，切换或补充表格索引；
- 来源冲突时，不补写，直接标记 `conflicting`。

跨字段证据复用只适用于契约别名或实体一致且值类型兼容的字段；复用证据必须标记低置信度，并不能直接触发自动填充。

## 三、内容填充与校验

### 1. 类型化输出

Managed Writer 的输出从自由文本升级为 `TypedFieldDraft`：

- `scalar`：一个规范化值、显示文本和支持它的证据 ID。
- `enumeration`：去重后的有序值列表，每项拥有证据 ID。
- `paragraph`：有长度上限的文本与逐断言证据。
- `repeating_table`：首期生成结构化候选行，但不自动新增工作表行。

Writer 只能基于已经筛选的 evidence package 工作。LLM 不可用时，只有能被确定性解析器抽取的标量/枚举才降级生成；不能将所有证据全文拼接写入单元格。

### 2. 自动填充门槛

字段必须同时满足才可自动写入：

- 字段契约为 `auto_if_verified`，目标区域为 placeholder 或合格 sample value。
- 至少一条来源和能力均匹配的冻结证据。
- 值能通过对应 `value_schema` 解析、归一化和长度限制。
- 不存在多来源不一致、模板污染或跨字段一致性冲突。
- 非降级、非跨字段复用、非自适应恢复的低置信度证据。

任一条件不满足，字段不写入并记录 `needs_schema`、`insufficient_evidence`、`conflicting` 或 `requires_human`；生成的候选仅在所有必填字段通过时进入 `waiting_human_approval`。

## 四、发布阶段和可观测性

Work Order、Evidence Matrix 和 Validation Report 增加字段级记录：契约版本、单元角色、覆盖理由、原始/改写查询、检索器、入选/淘汰证据、抽取值、校验结果和自动/人工决定原因。前端显示“未填原因”和证据，而不是把失败隐含为普通空单元。

模板自动激活指标与文档生成指标分离：模板可激活只说明字段区域合法；候选可进入审批取决于字段检索和填充验证。

## 五、分期与验收

### Phase 1：安全回归与查询打通

- 取消“任意 LLM 目标即全信任覆盖”的行为。
- 将 `query_terms`、别名和描述写入真实检索查询。
- 增加标量字段证据预算和无证据不填规则。

验收：固定标签零自动覆盖；字段查询日志含 query terms；无支持证据的字段不产生 FillPlan 项。

### Phase 2：模板结构与字段契约

- 实现 Workbook 结构分区和候选填写区。
- 引入字段契约、样例覆盖理由和 `needs_schema` 状态。
- 迁移现有模板分析/激活流程。

验收：常规模板中固定标签、表头和布局空白的误映射率显著下降；样例字段可在证据充足时自动填充。

### Phase 3：受控多源检索与类型化填充

- 实现契约驱动的检索路由、缺口补检和证据截断。
- 实现 TypedFieldDraft、值解析和字段级验证。
- 调整 FillPlan，只写入通过自动填充门槛的字段。

验收：多数常规模板生成后进入 `waiting_human_approval`；低置信度或冲突字段不会被自动写入。

### Phase 4：评测与发布门槛

建立由真实模板、冻结来源和人工标注期望组成的回归集，并在 CI 中统计：

- 模板字段映射 precision / recall；
- 固定内容误覆盖率；
- 字段 Recall@k、来源合规率和冲突率；
- 字段填充正确率、证据支持率、自动审批率和人工退回率；
- 分模板类型与字段类型的指标。

首期发布门槛：固定内容误覆盖率为 0；来源越界为 0；必填字段无证据自动填充为 0。自动审批率和字段填充正确率以标注基线为准，未达到项目设定阈值的模板类型保持人工审核。

## 风险与缓解

- 模型误判样例值：覆盖理由必须与规则分区一致，并保存为审计记录。
- 多源召回噪声：按字段能力路由、去重、预算和类型校验，不把全量结果交给 Writer。
- 缺少模板语义：用 `needs_schema` 显式暴露，不把猜测转为文档事实。
- 性能下降：字段并发受 HarnessPolicy 预算控制；检索与 Writer 各自记录耗时和命中。
- 既有模板兼容：保留旧 Schema 读取；缺字段契约时只进入兼容的人工审核路径，不自动扩大写入范围。
