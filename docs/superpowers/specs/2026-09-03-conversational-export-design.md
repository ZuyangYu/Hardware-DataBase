# 对话式导出与结构化文档生成设计

- 日期：2026-09-03
- 状态：Proposed，等待用户审阅
- 关联设计：[2026-09-02-agent-artifact-export-design.md](./2026-09-02-agent-artifact-export-design.md)
- 范围：知识库检索、结构化查询、普通对话和文档生成结果的对话式导出

## 1. 背景与现状问题

当前系统已经具备 `ResultSnapshot`、`ExportJob`、后台 export worker 和多格式渲染器，但“用户要求文件”与“导出交付”之间仍有断点：

1. 服务端 `infer_export_intent` 只识别少量动作词，`给出 PDF 文件` 中的“给出”不会触发导出计划。
2. 助手消息上的 `ExportMenu` 对所有带 `turn_id` 的消息固定展示，用户不能区分“系统识别出的自动导出”和“手动另存为”。
3. 前端手动导出流程依赖用户先选择格式，然后才调用 `/api/v1/exports`；自动计划没有在消息卡片中形成直接交付链路。
4. `envelope_from_turn` 保存的是最终回答、表格和证据；渲染器虽然有基础标题和表格处理，但没有根据用户要求先做内容重组。PDF、Word、PPT 对回答正文仍主要按普通文本处理，Excel 在没有可靠表格时也无法自动推断业务字段。

目标交互是：用户在对话中说清楚要什么文件和如何组织内容，系统生成正常回答，同时异步生成一个按要求整理的 Artifact，完成后直接在原消息下提供下载操作。用户没有指定结构时，使用对应格式的默认模板。

## 2. 目标与非目标

### 2.1 目标

1. 识别“给出、提供、请给我、直接给我、制作、做成、整理成”等自然语言文件交付表达。
2. 用户明确指定单个或多个格式时自动创建后台导出任务，不再要求重复选择格式。
3. 支持用户通过自然语言规定标题、章节、字段、排序、摘要、引用、受众、语气、页数/页数上限、幻灯片数量和风格。
4. 用户未规定的部分由格式默认模板补齐。
5. 导出内容经过结构化规划和格式适配，不把原始对话机械地改成不同扩展名。
6. 导出任务在原助手消息中显示“生成中/可下载/失败”，完成后显示文件名和下载操作。
7. 普通检索问题不因提及 PDF、Word 或 Excel 而触发导出。
8. 保留手动导出能力，但将其收进消息的“更多操作/导出”入口，并支持补充结构要求。

### 2.2 非目标

1. 不允许模型生成二进制、访问本地任意路径、执行 Shell 或调用外部转换脚本。
2. 不改变知识库检索范围、权限和证据授权逻辑。
3. 不承诺从非结构化回答中凭空恢复不存在的表格字段。
4. 不把用户的格式要求当作对事实的授权；内容重组不能增加无来源事实。
5. 本期不做在线 Word/PDF 编辑器；复杂编辑仍通过重新发送导出要求完成。

## 3. 产品规则

### 3.1 自动导出触发规则

高置信度的“文件交付”表达自动导出：

```text
给我一个 PDF 文件
请把刚才的检索结果整理成 Excel
直接输出一份 Word 报告，按背景、结论、证据、建议组织
制作 8 页 PPT，面向技术评审
```

只提到源文件格式而没有要求生成文件时不导出：

```text
PDF 中的芯片额定电压是多少？
Excel 里有哪些电源型号？
Word 文档第 3 页写了什么？
```

无法确定格式时不擅自创建文件；可以继续回答问题，并在必要时询问用户希望的格式。

默认行为：

- 单一明确格式：直接生成该格式并在消息中交付；
- 多个明确格式：全部生成，在同一消息中展示多个文件；
- 只指定“文件/文档”但未指定格式：不自动导出，询问格式；
- 只提及 PDF/Excel/Word 等源文件：按普通检索处理；
- 用户没有结构要求：使用格式默认模板；
- 用户要求与系统安全、事实证据或格式能力冲突：安全和事实约束优先，并在文件卡片中显示降级说明。

### 3.2 要求优先级

```text
系统安全与数据真实性
  > 用户明确格式/结构要求
  > 格式默认模板
  > 渲染器默认样式
```

用户明确要求只覆盖对应字段。例如用户只说“生成 PDF”，使用 PDF 默认结构；用户说“按摘要、问题、结论、证据、建议排列”，只覆盖章节顺序，其余仍采用 PDF 默认样式。

## 4. 统一导出请求模型

扩展现有 `ExportPlan`，继续将其序列化到 `chat_turns.export_plan_json`，并在 API 的 `TurnView` 中返回给前端：

```json
{
  "formats": ["pdf"],
  "delivery": "direct",
  "content_shape": "report",
  "title": null,
  "language": "zh-CN",
  "include_citations": true,
  "structure": {
    "sections": ["摘要", "主要问题", "结论", "证据", "建议"],
    "exclude": ["原始对话"],
    "ordering": "user"
  },
  "format_options": {
    "max_pages": 3,
    "theme": "professional"
  },
  "source_instructions": "按技术评审用途整理，突出风险和待确认项"
}
```

字段约束：

- `formats` 只允许 `md/xlsx/docx/pdf/pptx`，服务端统一 `markdown/excel/word/ppt` 别名；
- `delivery` 为 `direct` 或 `manual`；自然语言明确索要文件时使用 `direct`；
- `content_shape` 保留现有 `report/data/raw`，Excel 默认 `data`，其余格式默认 `report`；
- `structure.sections`、`exclude`、字段清单和排序规则均限制长度和数量；
- `format_options` 按格式用 Pydantic schema 校验，未知字段拒绝；
- `source_instructions` 只作为内容规划输入，不得被当作代码、路径或外部 URL 执行；
- 用户指令、格式和选项纳入幂等哈希，重复请求不重复创建同一任务。

## 5. 意图识别与请求规划

### 5.1 第一层：服务端高置信度识别

扩展现有 `src/result_exports/intent.py`：

1. 增加“给出、提供、请给我、直接给我、制作、做成、整理为”等动作表达；
2. 增加“文件、附件、报告、文档、下载、格式”等交付证据；
3. 保留源文件询问的否定/上下文保护规则；
4. 识别格式别名、页数、章节名、列名和明显的排除要求；
5. 无法可靠识别时返回 `None`，不自动导出。

这一层不负责自由改写用户内容，只产生安全的初始 `ExportPlan` 和原始 `source_instructions`。

### 5.2 第二层：结构化导出规划器

新增受控的 `ExportDocumentPlanner`，由后台 worker 在 ResultSnapshot 已完成后调用。规划器接收：

- 用户原始导出要求；
- 最终回答；
- 结构化检索结果；
- 证据和来源定位；
- `ExportPlan` 和格式默认模板。

规划器只输出经过 schema 校验的 `ExportDocument`，不生成二进制：

```text
ExportDocument
├── title
├── summary
├── sections[]: heading / paragraphs / bullets
├── tables[]: name / columns / typed rows / citation refs
├── citations[]
├── notes[]
└── layout_hints: page/slide/sheet guidance
```

规划提示必须要求：

1. 只重组和压缩已有事实，不补造数据；
2. 用户要求的字段缺失时标记“未找到/待确认”；
3. 每个结论和表格行尽可能保留来源引用；
4. 原始对话默认不进入报告正文，除非用户明确要求 `raw` 或保留对话；
5. 表格/SQL 结果优先使用真实结构化行，不从自然语言回答反推数值；
6. 用户的章节顺序、标题和排除项覆盖默认模板。

规划器输出必须经过版本化 JSON schema 校验。模型不可用、超时或输出不合法时，任务进入可重试流程；超过重试次数后使用确定性降级渲染，并在 Artifact 预览/消息卡片中明确标记“未完成智能整理”。

同一批次的多个格式应尽量复用同一个 `ExportDocument`，不同格式只负责版式适配。可通过 `document_plan_hash = snapshot_id + normalized_plan` 做缓存和幂等，避免用户同时要求 PDF、Word、PPT 时重复规划。

## 6. 内容默认模板

### 6.1 PDF / Word 报告

默认结构：

1. 标题；
2. 摘要；
3. 关键结论；
4. 详细分析或检索结果；
5. 表格与数据；
6. 风险/待确认项；
7. 参考来源。

不默认包含完整原始对话，不把 Markdown 标记原样显示为正文。

### 6.2 Excel

默认结构：

- `结果数据`：真实结构化结果、规范列名、数值/日期/布尔类型；
- `查询说明`：问题、生成时间、内容形态；
- `参考来源`：文件名、定位、证据摘录和引用关系。

如果没有可靠的结构化结果，默认生成“结果说明”工作表并标明缺少结构化数据，不伪造列值。

### 6.3 PowerPoint

默认结构：

1. 标题页；
2. 执行摘要/关键结论；
3. 证据和数据页；
4. 风险与建议；
5. 参考来源。

默认一页只承载一个主要观点；存在可靠数字表格时才自动生成图表。用户指定页数、受众、主题或讲稿要求时覆盖默认规则。

### 6.4 Markdown

默认输出层级标题、摘要、结论、表格、引用和来源，不直接保存完整聊天 transcript。

## 7. 后端数据流

```text
用户消息
  ↓
intent parser 生成 ExportPlan
  ↓
ChatTurn 持久化（包含用户原始导出要求）
  ↓
Agent 检索与回答
  ↓ 同一事务
ResultSnapshot + ExportJob + outbox
  ↓
ExportWorker claim/lease
  ↓
ExportDocumentPlanner（一次/批次复用）
  ↓
RendererRegistry 按格式排版
  ↓
Artifact 校验、原子发布
  ↓
消息内任务卡片和任务中心更新
```

ResultSnapshot 保持不可变，用户后续修改导出结构时创建新的 ExportJob/派生文档计划，不修改历史快照。导出 worker 不依赖浏览器连接；页面切换、刷新和切换会话不影响任务。

## 8. API 与前端交互

### 8.1 API

扩展 `TurnView`：

```json
{
  "export_plan": {
    "delivery": "direct",
    "formats": ["pdf"],
    "content_shape": "report",
    "structure": {},
    "format_options": {}
  }
}
```

扩展 `ExportJobView`/`ExportArtifactView` 返回：

- `delivery`；
- `source_title` 或 `source_query_preview`；
- `content_shape`；
- `filename`、`size`、`expires_at`；
- `planning_status` 和可选的降级说明。

手动导出 `POST /api/v1/exports` 支持同一套 `structure`、`format_options` 和 `source_instructions`，服务端重新校验，不信任浏览器传来的格式或路径。

### 8.2 消息卡片

- `delivery=direct`：隐藏常驻格式下拉框，显示“正在生成 PDF…”；完成后显示“下载 PDF 文件名”；
- 多格式：显示一个导出卡片，每种格式一行状态和下载操作；
- `delivery=manual`：消息不显示导出控件，放入“更多操作 → 导出/另存为”；
- 普通检索问题：不显示格式选择器；
- 下载仍通过带认证的 `downloadBlob`，避免把 Bearer token 暴露给普通链接。若未来确需可复制的 HTML 链接，再增加短期签名 URL。

任务中心保留为跨页面的后台状态入口，迁移到左侧全局导航；它不是用户触发导出的前置步骤，只负责查看状态、重试、取消和下载。

## 9. 错误处理与安全

1. 格式不支持、选项非法或请求超限：在任务创建前返回 400/409，不创建任务。
2. 规划器超时或输出 schema 不合法：按任务重试策略处理，不影响原聊天回答。
3. 结构要求不可满足：尽可能生成可用文件，并在文件卡片中列出未满足项。
4. 证据不足：使用“未找到/待确认”，不生成推测性字段。
5. 文件扩展名、MIME、Office 包、PDF 可解析性、大小和页数均由后端校验。
6. 下载和预览时重新检查用户、租户、部门和知识库权限。
7. 会话删除时同步删除关联 ExportJob、Artifact 和磁盘文件；worker 发现会话已删除后丢弃迟到结果。
8. 导出文件保留期仍由现有 retention 配置控制；会话删除优先级高于普通过期保留。

## 10. 测试与验收

### 10.1 意图和计划

- `给出pdf文件` → `direct + pdf + 默认 report`；
- `请按摘要、结论、证据整理成 PDF` → 保存章节顺序；
- `生成 Excel，列为型号、参数、数值、来源` → 保存字段约束；
- `制作 8 页 PPT，面向技术评审` → 保存页数和受众；
- `PDF 中的额定电压是多少` → 不生成；
- `不要导出 PDF` → 不生成；
- 非法页数、未知选项、超长结构要求 → 拒绝或裁剪并给出明确错误。

### 10.2 端到端

1. 明确要求 PDF 后，聊天仍正常完成，后台创建 PDF ExportJob。
2. 页面切换后任务继续，回到原会话能看到同一任务。
3. 任务完成后原助手消息出现下载操作，不能再次显示格式下拉框。
4. 多格式要求生成多个独立 Artifact，单个格式失败不影响其他格式。
5. 删除会话后任务中心、消息卡片和下载 API 均不再暴露对应文件。
6. 其他会话、其他用户和无关 Artifact 不受影响。

### 10.3 内容质量

- PDF/Word 有真实标题层级、章节、表格和引用；
- Excel 使用真实结构化行和类型，不把整段回答塞进唯一单元格作为默认结果；
- PPT 按页组织观点，长回答不会全部挤入单个文本框；
- 用户指定章节、字段、页数和排除项生效；
- 规划器失败时确定性降级可下载且有提示；
- 生成内容不出现未被源结果支持的事实。

## 11. 实施阶段

### Phase 1：自动交付闭环

1. 扩充服务端意图识别和 `ExportPlan`；
2. 将计划返回到 `TurnView`，前端隐藏常驻 `ExportMenu`；
3. 在消息中展示自动任务状态和完成后的下载操作；
4. 补齐来源标题、问题摘要和文件名展示。

### Phase 2：结构化内容规划

1. 增加 `ExportDocument` schema 和 planner worker 接口；
2. 实现用户章节、字段、引用、受众、页数和风格要求的合并规则；
3. 让多个格式复用同一份派生文档计划；
4. 为规划器增加事实约束、超时、重试和确定性降级。

### Phase 3：格式质量和任务中心

1. 改造 PDF/Word/PPT/Excel 渲染器消费 `ExportDocument`；
2. 将手动导出设置收进“更多操作”对话框；
3. 任务中心迁移到左侧全局导航并完善说明；
4. 完成会话删除时的任务、Artifact 和物理文件清理。

每个阶段均先补测试，再修改实现；Phase 1 未闭环前不宣称“ChatGPT 式直接交付”已完成。
