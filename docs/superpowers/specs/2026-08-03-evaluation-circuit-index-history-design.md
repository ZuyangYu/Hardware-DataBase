# Evaluation, Circuit Index, and History Integration Design

## Goal

Improve evaluation latency and completion UX, make parsed EDF facts reliably
available to question answering, and import complete historical evaluation
reports from the primary checkout into the template-authoring worktree for
safe viewing and cohort-compatible comparison.

## Scope

This change extends the existing evaluation, circuit ingestion, circuit
retrieval, and Streamlit history components. It preserves the current EDF
parsers, `CircuitStore`, RAGFlow document retrieval, report schemas, and source
evaluation directory. It does not introduce a graph database or migrate
snapshot-only/incomplete evaluation runs.

## Evaluation Runtime and Completion UX

Evaluation will use explicit defaults intended for interactive operation:
short evaluator timeouts, no opaque upstream retries, one context-budget
attempt, a bounded scoring context, and a bounded output-token budget. Every
setting remains configurable through `EVAL_*` environment variables. The
application must not inherit a substantially larger general-agent timeout when
no evaluation-specific timeout is present.

The existing metric-group checkpoints remain the unit of progress and
cancellation. A timed-out group becomes failed metric results and later groups
continue. Completed, partial, cancelled, and failed reports retain the same
artifact names and completion marker.

The active Streamlit fragment continues polling every two seconds. When it
observes a terminal run with a finalized report, it triggers exactly one
application-level rerun. The outer evaluation page then selects and renders
the report automatically instead of leaving the user on a stale status panel.

## Circuit Ingestion and Indexing

`CircuitIndexService` becomes the single ingestion boundary for all derived
EDF artifacts. After parsing and validating a `CircuitDesign`, it performs:

1. atomic structured-state persistence through `CircuitStore`;
2. connectivity graph persistence;
3. per-design vector reindexing; and
4. global registry update through the existing store save.

Structured state remains the authoritative artifact. Graph or vector failures
do not discard a valid parse, but the result is marked degraded and carries a
specific warning. An upload is reported as fully indexed only when each
configured index succeeds or is explicitly unavailable by configuration.

The connectivity graph uses a component-pin-net representation:

```text
Component(refdes) --contains--> Pin(refdes.pin) --on_net--> Net(name)
```

This avoids the quadratic clique generated by connecting every component pair
on large power/ground nets. Nodes retain design ID, source name, part number,
value, net type, and direct EDF provenance needed by downstream evidence.

The existing per-KB vector index continues storing module, instance, and net
documents. Reindexing is invoked from the real upload path, scoped by design
ID, and remains a no-op with an explicit unavailable status when no embedding
model is configured.

## Circuit Retrieval Routing

Question analysis deterministically enables circuit entity/relationship
retrieval for hardware-structural signals including:

- component reference designators and net names;
- pin, connection, pull-up/pull-down, resistor value, and placement questions;
- crystal/oscillator frequency and clock-source questions;
- enable, inhibit, wake-up, and power-path questions.

Retrieval order is exact structured lookup, graph relationship lookup,
optional circuit semantic lookup, then RAGFlow document evidence. Direct EDF
facts rank above narrative document chunks. Results are deduplicated by stable
evidence identity and retain file/entity/pin/net locators.

The five `ai_database_test.jsonl` hardware questions form the initial routing
regression set. In particular, indexed facts for `Y900`, `Y600`, `R1205`, and
`U1600` must be discoverable without depending on document-vector recall.

## Historical Evaluation Import

A command-line importer copies only directories containing at least
`summary.json` and `results.jsonl`. The source checkout is always read-only.
The importer supports dry-run and apply modes and records, for every accepted
run:

- source path and original directory name;
- hashes of copied artifacts;
- import timestamp;
- sample-ID cohort fingerprint; and
- validation warnings.

Apply mode copies into a temporary directory under the target evaluation root,
verifies hashes, writes `import_manifest.json` and `report_complete.json`, then
atomically renames the directory. Existing equal-content runs are skipped.
An existing run with different content is never overwritten; it is reported
as a conflict requiring manual resolution.

The initial import source is:

`/home/user/workspace/Hardware-DataBase-integrate-develop/storage/evaluations`

The target is the worktree's `storage/evaluations`. Snapshot-only directories
and runs missing either summary or per-sample results are excluded. The
currently observed source contains 26 eligible complete reports and no run-ID
overlap with the two target reports.

## Cohort-Compatible Comparison

The history UI computes a cohort fingerprint from the sorted sample IDs in
`results.jsonl`. Baseline candidates default to runs with the same fingerprint.
Runs from other cohorts remain viewable but cannot be selected as a numerical
baseline, preventing misleading comparisons between the historical 15-sample
suite and the newer 5-sample suite.

Older reports need no schema rewrite: origin and cohort information is read
from the import sidecar or computed at load time. Imported origin and sample
count are visible in the history selector and report header.

## Error Handling and Safety

- Parser validation failures stop indexing and preserve the prior indexed
  design.
- Derived graph/vector failures are surfaced as degraded-index warnings.
- Evaluation timeouts are recorded per metric group and never hold the entire
  report open through multiple hidden retries.
- Page auto-refresh is guarded so terminal reports do not cause rerun loops.
- Historical import never mutates the source, never overwrites different
  target content, and never publishes a partially copied run.
- API keys, prompts, upstream response bodies, and unrelated worktree changes
  are excluded from reports and commits.

## Testing

Tests will cover:

- evaluation-specific defaults, timeout behavior, and terminal app rerun;
- component-pin-net graph topology without same-net component cliques;
- real ingestion invocation of graph persistence and vector reindexing,
  including degraded outcomes;
- exact retrieval of `Y900`, `Y600`, `R1205`, and `U1600` facts;
- deterministic circuit routing for the five evaluation question patterns;
- importer dry-run, eligibility, source immutability, hash verification,
  conflicts, corrupt reports, and atomic publication;
- cohort fingerprint stability, compatible baseline filtering, imported-run
  labels, and legacy report readability; and
- the complete evaluation, circuit, ingestion, and evaluation-page regression
  suites.
