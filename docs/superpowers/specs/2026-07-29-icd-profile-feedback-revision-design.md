# ICD Profile、证据约束与反馈修订设计

## 目标

在保留通用文档生成能力的前提下，识别 ICD 模板并启用受约束的
ICD 生成路径。该路径必须从项目资料取得可追溯事实，以同一份冻结
电路映射填充管脚表和前视图；生成错误时阻止发布，并让反馈形成有限
次数的修订候选，而非只保存评论。

## 背景与问题

`artifact-668a882501504efb8216a549c9530f15.xlsx` 与人工 ICD
`600608964_ADAS_ICD_0506_1957_shoulin.wang.xlsx` 的比较显示：人工
文档的 X1900 与 X1902 共 18 个管脚，在产物中没有一个匹配。产物使用了
X302 示例页，并将检索段落写入 Location Number。这说明通用检索、自由写入
和发布前校验不足以满足 ICD 的确定性需求。

项目资料足以支持正确生成：EDF/EDIF 提供接插件、管脚和网络；需求、FPT
和 HSI 提供型号、产品身份与接口语义；正式模板提供表格和前视图的槽位。
芯片数据手册是可选的能力或冲突校验来源，不能替代项目实际连接事实。

## 范围

- 以数据驱动方式识别 `generic`、`icd` 与 `icd_sample` Profile；不得根据
  项目名、固定 RefDes、固定管脚数或模板坐标判断。
- ICD 正式生成使用冻结来源、范围决策和 EDF 管脚映射。
- 字段级来源策略、格式约束、前视图确定性填充和发布门禁。
- 将反馈转换为受限的修订工作，而不是只记录不可执行评论。
- 保持非 ICD 文档当前的通用生成路径。

## Profile 与模板契约

模板分析产生 Profile 及其置信理由：

- `generic`：不具备 ICD 组合特征，沿用通用生成。
- `icd`：存在可写的管脚定义块，以及 `Pin Number`、`Pin Definition`、
  `Location Number`、接插件型号或前视图等 ICD 特征的可靠组合。
- `icd_sample`：模板仅有示例块、示例命名或缺少正式 ICD 必需结构。它可用于
  预览/演示，但不能发布正式 ICD。

ICD 模板契约由模板本身派生，不要求固定工作表数量。正式 ICD 至少要有：

1. 产品身份槽位；
2. 一个或多个可定位的接插件块；
3. 每块的 Location Number、板端型号、Pin Number 和 Pin Definition 槽位；
4. 可选的线束端型号、功能、备注与前视图槽位。

契约解析失败或发现的仅是示例区域时，系统创建清晰待办，不运行正式 ICD
渲染。

## ICD 事实与填充规则

| 目标字段 | 允许的主要来源 | 写入规则 |
| --- | --- | --- |
| Location Number、Pin Number、Pin Definition、NC | EDF/EDIF | 使用冻结的接插件—管脚—网络映射确定性写入 |
| 板端型号 | 需求/FPT，必要时原理图 | 必须有直接来源 |
| 线束端型号 | 需求/FPT | 必须有直接来源 |
| 产品名、客户号 | FPT、需求或项目身份资料 | 必须有直接来源 |
| 功能、预留、备注 | 需求/HSI | 缺证据时留待补充，不得猜测 |
| 前视图 | 模板槽位 + 冻结 EDF 映射 | 与 Pin Definition 使用同一事实快照 |
| 芯片数据手册 | 可选校验 | 不能证明项目外部接插件实际连接 |

范围决策从模板的接插件槽位、FPT/需求中的直接引用和前视图格位共同取得候选，
再仅查询候选范围内的 CircuitStore。接插件不明、EDF 缺映射、额外真实管脚
是否暴露不明、或来源冲突时，创建异常待办。用户仅处理这些少数例外。

Location Number 须满足模板声明的接插件标识格式；长文本、检索段落和不属于
冻结范围的值均为阻断错误。

## 生成、校验与发布

```text
模板 Profile/契约
  -> 冻结来源与 ICD 接插件范围
  -> EDF 管脚映射 + 文档语义证据
  -> 确定性 Pin Definition / 前视图填充
  -> 字段级校验与只读预览
  -> review_candidate 或阻断待办
  -> 显式批准 -> approved_release
```

发布门禁至少验证：

- 选用的是 `icd` 正式模板，而不是 `icd_sample`；
- 接插件范围和冻结来源已确定；
- 每个受管接插件存在 EDF 映射；
- Pin Definition 的集合、网络和 NC 状态与冻结映射一致；
- 必填身份、型号字段有允许来源且满足格式；
- 前视图格位可解析，并与 Pin Definition 一致；
- 不存在未关闭的异常或修订反馈。

## 有界反馈修订

反馈继续保留为不可变审计事件，并另建修订请求。请求带有候选内容哈希、来源
快照、目标字段/问题类别和简短评论。可自动处理的类别仅限：缺失字段证据、
字段格式、语义补充、前视图/管脚一致性。修订仅重新检索或重渲染受影响字段，
且不得扩大冻结来源集合。

每个候选最多自动创建两次修订候选。需要新资料时，系统提示用户上传指定资料，
并在新来源快照下创建新的工作单修订。超过上限或仍有阻断问题时，输出待办，
不得发布。

## 组件职责

- Profile/模板契约组件：识别文档类型和可写结构。
- 证据规划组件：根据字段来源策略建立检索需求。
- 电路事实组件：从 EDF/EDIF 输出完整可追溯管脚事实。
- ICD 渲染组件：只使用冻结映射填充 ICD 表格和前视图。
- 独立校验组件：验证字段、管脚集合、布局和来源。
- 反馈路由组件：创建有界修订或用户待办。

这些职责是服务内受控组件，不允许一个通用 Writer 自行决定接插件范围或改写
结构化电路事实。

## 测试与验收

1. Profile 测试：正式 ICD、示例 ICD 与普通模板识别正确；示例不可发布。
2. 绑定测试：Location Number 拒绝长文本；型号/产品字段拒绝无允许来源值。
3. ICD 集成测试：以真实结构的夹具验证两组接插件、完整管脚、型号与前视图共用
   同一冻结映射。
4. 对比回归：当前 ADAS 基准与人工 ICD 的有效管脚匹配率和覆盖率均为 100%；
   同时保留跨项目夹具，证明没有 X1900/X1902 特例。
5. 反馈测试：反馈产生受限修订候选；未解决反馈、超过修订上限或新资料缺失时
   均不能发布。

## 非目标

- 不要求所有芯片数据手册作为 ICD 生成输入；
- 不用人工 ICD 作为新项目的生成事实来源；
- 不自动修复没有来源支持的工程结论；
- 不改变 generic Profile 的既有模板写入行为。
