# 模板建议目标冲突消解设计

## 背景

模板建议器会把可写单元拆成多个 LLM 批次，再合并各批次返回的建议。当前分析校验只检查目标单元是否存在、是否可写，没有检查同一目标是否被多个建议占用。重复目标因此能以 `ready_for_confirmation` 状态持久化，直到自动启用创建绑定时才以 `suggested template targets may only be bound once` 失败。

本次故障中，`checklist_data`（置信度 0.8）和 `checklist_row_28`（置信度 0.5）同时选择了 G28:N28，导致六轮 LLM 调用完成后仍无法启用模板。

## 目标

- 在 LLM 批次结果合并后，以确定性规则消解重复目标。
- 优先保留置信度更高的建议，不允许一个模板单元生成多个绑定。
- 在分析阶段验证最终结果，使冲突不再延迟到激活阶段暴露。
- 保留现有的目标存在性、可写性和激活阶段唯一性防线。

## 非目标

- 不放宽“一处模板目标只能绑定一次”的发布约束。
- 不合并不同建议的语义 ID、标签或检索词。
- 不猜测未知目标，也不把不可写目标转换为可写目标。
- 不增加新的 LLM 调用或冲突重试。
- 不修改已经持久化的历史分析草稿。

## 方案

采用高置信度优先的安全去重：

1. 建议器完成全部 LLM 批次并合并结果。
2. 在去重前校验所有目标均存在且可写，防止非法低优先级目标因冲突而被静默删除。
3. 为目标分配建立优先级视图：置信度降序，置信度相同时按 LLM 合并结果中的原始顺序。
4. 对每条建议，按原顺序保留尚未被更高优先级建议占用的目标。
5. 若建议仍有目标，则保留建议及其未冲突目标；若目标全部被占用，则删除该建议。
6. 按原始合并顺序输出所有仍被保留的建议，执行包含全局唯一性的最终校验，再写回分析对象。

该规则不修改输入列表或建议对象，而是产生新的建议列表，避免部分失败时污染原始分析状态。

## 校验边界

`TemplateAnalysis.validate_suggestions()` 增加全局目标唯一性校验。它仍先确认目标存在且可写，同时记录已见目标；再次遇到同一目标时抛出明确的 `ValueError`。

该校验是 provider 无关的契约：LLM provider 会在调用前主动消解冲突，其他 provider 若提交重复目标则在分析阶段被拒绝。激活阶段 `_regions_and_bindings()` 的现有检查继续保留为纵深防御。

未知目标或不可写目标不是可自动修复的歧义，仍按现有技术失败或人工处理路径终止，不得被冲突消解吞掉。

## 数据流

`分批 LLM 输出 → 合并 → 目标合法性校验 → 高置信度优先消解 → 全量唯一性校验 → 持久化分析 → 自动启用 → 创建唯一绑定`

冲突消解是纯本地操作，不改变进度事件总批数，也不产生额外 LLM 调用。正常无冲突输出保持原有顺序与内容。

## 测试

- 高置信度建议优先占用重复目标。
- 低优先级建议部分冲突时保留其非冲突目标。
- 低优先级建议全部冲突时被删除。
- 相同置信度时按原始合并顺序稳定选择。
- 无冲突建议保持原顺序和目标顺序。
- 未知目标和不可写目标仍然失败。
- 非 LLM provider 的重复目标在分析校验阶段被拒绝。
- 自动启用对消解后的建议创建唯一 regions 和 bindings。

## 验收标准

- 本次 G28:N28 类型的高、低置信度冲突不再导致自动启用失败。
- 任一目标在最终建议中最多出现一次。
- 冲突消解不增加 LLM 请求次数。
- 非法目标不会因去重而被接受。
- 相关建议器、分析契约、上传与自动启用测试通过。
