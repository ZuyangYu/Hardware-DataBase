## A. 单源基线（先确认各源单独可用）

### A1 器件引脚→网络（纯电路）
**问题**：`U1700 的每个引脚分别连接到哪个网络？`
**期望答案（真实）**：应走 `circuit_query`，列出 LP87702-Q1（料号 20200424007）的引脚映射，关键几条必须正确：
- `VIN_B0_1 / VIN_B1_1 / VANA / VIN_B0_2 / VIN_B1_2 → VCC3V3`（输入 3.3V）
- `FB_B0 → VCC1V1`、`FB_B1 → VCC1V8`、`VOUT_BST → VCC50`（三路输出反馈/升压）
- `EN1 → MCU_5V_EN`、`WD_RESET → TC367_RESET_N`、`SDA(EN3) → MCU_SDA_P15.5`、`SCL(EN2) → MCU_SCL_P15.4`
- 多个 `PGND_* / AGND / PAD → GND`
**判据**：命中的是结构化电路证据（content_kind=circuit_design），引脚-网络对应无编造；`VMON1/VMON2/PG0/GPO0` 为未连接（None）应如实说明或省略。

### A2 网络上挂了哪些器件（纯电路）
**问题**：`网络 VCC3V3 上连接了哪些芯片？`
**期望答案（真实）**：`VCC3V3` 共 52 个连接，其中 IC 级至少应命中：
- `U1700`（PMIC，多个 VIN 引脚）、`U1800.VIN`（TPS62872 buck）、`U1500.VIN` / `U1802.VIN`（TPS22918 负载开关）、`U1804.VIN`、`U1600.VCCIN`
**判据**：命中 `search_net_connections`；答案说明 VCC3V3 是给多个电源器件供电的主 3.3V 轨，不把电容/电阻当成"主要负载"来强调。

### A3 纯文档（验证项目上下文硬路由）
**问题**：`ADAS 项目的软硬件接口文档里，硬件架构包含哪些模块电路？`
**期望答案（真实）**：应走 `document_rag`，从 HSI 文档 2.3 节列出模块电路，真实章节包括：
KL30 电源管理电路、唤醒电路、电源电路、TC377 最小系统、EQ6 最小系统、摄像头最小系统、看门狗电路、温度采样电路、系统内电源电压采样电路、ETH 电路、CAN/CAN FD 电路、3V3 过压保护电路。
**判据**：`_has_project_context`（"项目/ADAS"）应把它锁成 hardware_kb_query 走检索，绝不能判成 general_knowledge 直接答。

## B. 真正的联合检索（circuit + doc 必须都命中并融合）

### B1 电路拓扑 + 文档配置融合 ★核心
**问题**：`给板子供电的主 PMIC 是哪颗？它输出哪几路电压，软件是怎么配置它的？`
**期望答案（真实）**：
- **电路侧**（circuit_query）：主 PMIC 是 **U1700 = LP87702-Q1**（料号 20200424007），输入 VCC3V3；输出至少三路：`VCC1V1`(FB_B0)、`VCC1V8`(FB_B1)、`VCC50`(VOUT_BST 5V 升压)；使能 `EN1 = MCU_5V_EN`，经 I²C（SDA/SCL 到 MCU P15.5/P15.4）配置。
- **文档侧**（document_rag）：HSI 文档 **7.2 节 "LP87702 配置"** 给出软件寄存器/I²C 配置说明。
**判据**：footer 检索诊断里 `circuit_query` 与 `document_rag` **都应有 hit**；答案按"器件识别→输出轨（电路证据）→软件配置（文档证据）"组织，且分别标注来源（EDF vs HSI）。这是最能体现"联合"的题。

### B2 0.75V 电源 + 文档配置
**问题**：`0.75V 这路电源是哪颗芯片产生的，输入是什么？文档里对它有配置要求吗？`
**期望答案（真实）**：
- 电路：**U1800 = TPS62872**（料号 202308165398），`VIN = VCC3V3`，`VOSNS = VCC0V75`（输出 0.75V），使能脚 EN 接 N19888813，I²C SDA/SCL 到 MCU。
- 文档：HSI **7.3 节 "TPS62872 配置"**。
**判据**：电路证据给出输入(VCC3V3)/输出(VCC0V75)网络，文档证据补充配置；两源都命中。

### B3 3V3 过压保护（拓扑 vs 文档能力，防幻觉）★
**问题**：`3.3V 电源有没有过压保护？是怎么实现的？`
**期望答案（真实）**：
- 文档侧：HSI **2.3.12 节 "3V3 过压保护电路"** 确有该电路，应据此说明保护存在。
- 电路侧：可命中 Diode/TVS 模块（Group 16）或相关网络的拓扑，但**只能陈述"观察到的连接/拓扑"**。
**判据**：答案区分"文档声明的保护功能"与"电路里观察到的器件连接"，**不得**把网表里看到的二极管拓扑直接断言成某个确定的过压阈值/保护能力（除非文档给出）。对应代码里 `derived_topology` vs `datasheet_claim` 的纪律。

## C. 多跳 / 枚举 / 缺口暴露

### C1 多个负载开关枚举（禁止归纳）★
**问题**：`板上用 TPS22918 做了哪些电源开关？每个的输入和输出分别是什么？`
**期望答案（真实）**：必须**逐个**列出三颗，不能归纳成"某一路"：
| 器件 | 输入(VIN) | 输出(VOUT/QOD) | 使能(ON) |
|---|---|---|---|
| U1500 | VCC3V3 | VCC3V3_ETH | MCU_3V3_ETH_EN |
| U1802 | VCC3V3 | VCC3V3_EQ | MCU_3V3_EQ_EN |
| U1803 | VCC1V8 | VCC1V8_EQ | MCU_1V8_EQ_EN |
**判据**：对应 compose_answer 提示"多个 power-control candidate 必须逐个按输入/输出网络列示"。三颗都在、输入输出网络对得上即通过。

### C2 电源树多跳（ETH 供电链）
**问题**：`以太网 PHY 的 1.0V 电源是怎么一级级供出来的？`
**期望答案（真实）**：一条链路：
`VCC3V3 → U1500(TPS22918, ON=MCU_3V3_ETH_EN) → VCC3V3_ETH → U1501(TPS74501 LDO) → VCC1V0_ETH`
（U1501：IN=VCC3V3_ETH，EN=VCC3V3_ETH，OUT=VCC1V0_ETH）
**判据**：需要多个 net/instance 证据串联；观察 judge_sufficiency 是否判定要多级、检索账本能否把这条链补全。

### C3 强制缺口（诚实缺失）
**问题**：`U1700(LP87702) 的替代料和采购单价是多少？`
**期望答案（真实）**：库里**只有电路+HSI 文档，没有 BOM/替代料/价格表**。正确答案应明确说明"知识库中未找到替代料/单价证据（缺失）"，只能给出已知料号 20200424007。
**判据**：**不得编造**替代料或价格；检索账本对应子问题 status 应为 missing，答案明确标注缺口。

## D. 冲突检测与鲁棒性

**期望答案（真实）**：
- 电路侧：`U900*` = **SAK-TC367DP-64F300S**（Infineon AURIX TC367，料号 20210903003）。
- 文档侧：HSI 目录写作 **"TC377 最小系统"**，参考文档为 "AURIXTC37x Safety Manual"。
**判据**：好的答案应指出主控为 AURIX TC3xx 系列，并如实反映"电路网表标 TC367 / 文档章节名写 TC377"这一**命名差异**，而不是随意二选一断言。可用于观察 `_detect_evidence_conflicts` 或答案层的冲突呈现。

**期望答案（真实）**：`circuit_query` 经部门过滤 `_ctx_department_id` 后返回空，答案应为"当前知识库中未找到可支撑回答的证据"，**不报错、不串库**。
**判据**：无异常堆栈；不会检索到 ADAS 的电路数据。

### D3 直答分流（对照组）

## 通过标准速查

| 维度 | 看哪里 | 通过标志 |

| 是否真联合 | footer 检索诊断 | 联合题中 circuit_query 与 document_rag 都有 hit |
