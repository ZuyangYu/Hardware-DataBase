## 2. 结论与剩余项

- 框图所需全部历史事实现在均有 MCP 调用背书，**不再依赖本地工作区文件**。
- 一个仍未直接取证的次要事实：PDF 第 20 页顶部标题 “DEBUG CONNECTOR”。两次 `hdb_ask_knowledge_base` 均失败（240s 流处理超时 / 120s 超时），但 HSI chunk 84 + chunk 76 已经给出 X2000 上挂 SPI0（EQ6↔MCU 数据）、WDI/RESET、JTAG 的完整信号构成，“调试/扩展接口”的角色判定已被等价覆盖，不影响框图结论。
- 待打合新增/denoise：
  - SoC↔MCU SPI0 实际**经 X2000 调试口布线**（HSI chunk 84 + 网表 X2000 pin53~60）——框图抽象为“SPI / RST / EN”，实现细节留给 ④ 接口表；
  - HSI 框图文字化描述（chunk 49）把 CAN 收发器写成 “TCAN1046A”——与网表三选贴（TCAN1145 / TCAN1044A / TJA1043）不符，可判读为图像转写误识，列为干扰信息不上图。

## 3. 试跑中暴露的 MCP 缺陷（对应排队中的优化）

| # | 缺陷 | 本次证据 |
|---|---|---|
| 1 | `hdb_download_kb_file` 直接报错：`cannot resolve the configured user for file download` —— 需要修的用户解析/会话参数传递 | 本次调用返回 error |
| 2 | `read_file_chunks` 只能从头拉 N 个，无 `start_index`/搜索 | HSI 370 chunks，前 100 恰好覆盖需求；PDF/XFI 若靠后则不行 |
| 3 | `ask_knowledge_base` 成功率低且不稳（本会话 4 失败 1 成功：额度+超时交替），且超时不返回任何部分证据 | Q2/X2000 240s 超时；F01-F28 问句额度受限；X2000 短问句 120s 超时 |
| 4 | `query_circuit` 每次都返回全套 summary+modules（噪音大），靠 harness 截断勉强可用 → “include_summary / 字段筛选 / MPN 家族分层检索”的优化仍然需要 | 本轮 ~20 次点查平均数百行输出 |
