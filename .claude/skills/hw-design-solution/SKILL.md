# 五步硬件方案方法论

从系统需求到整套硬件方案交付物的完整工作流。方法论来自实际项目多轮打磨沉淀：数值纪律、确认机制、绘制规范、自检工具链全部内建，照做即可少走弯路。

## 一、产出物清单（共 7 项）

| # | 文档 | 形态 | 依赖输入 |
|---|---|---|---|
| ① | 关键器件清单 | xlsx | 需求文档 + 资源库 |
| ② | 整体硬件方案框图 | drawio + PNG | ①（或选型定案）+ 电源轨表 + 接口信号 |
| ③ | 电源计算表 | xlsx | ① + 各芯片手册电流值 |
| ③+ | 电源树（分级图 L1/L2/L3） | drawio + PNG | ③ |
| ④ | 接口定义表 | xlsx | ②的信号清单 + ③的耗流 |
| ⑤ | 上下电时序表 + 时序图 | xlsx + drawio/PNG | 芯片清单 + 各芯片手册时序章节 |
| ⑥ | 热风险分析表 | xlsx（全公式链） | ③的功耗 + 各芯片手册热阻 |
| ⑦ | 硬件方案汇总 | md | 以上全部 |

依赖关系：①→②→④；③依赖①与②可并行；③+、⑤、⑥在各目前序完成后执行；⑦最后。

## 二、运行模式：先判断用户要哪种

**模式 A：单文档执行（最常见）**。用户点名一个文档（"生成框图""出接口表""做个热分析"）。动作序列：

1. 打开下方路由表，核对该文档的**必需输入**——从项目目录已有的定案文件（xlsx/drawio/md）里找；
2. 输入齐全 → 读完对应 reference 章节后直接执行该文档的生成流程；
3. 输入缺失 → 明确告诉用户缺什么，要么用户提供，要么确认是否需要先跑前置文档。不要在输入不齐时凭猜测开跑。

**模式 B：全流程**。用户给需求文档要整套方案。按依赖序推进，每完成一个文档交给用户确认，确认通过才进下一个。两个防崩纪律：

- 框图（②）是全流程中修复迭代最重的环节——其生成+自检循环必须整体交给子代理跑（见 workflow.md"子代理分工"），主会话只做确认与决策分发；
- 每个文档收工时，所有定案必须已落盘（文件形式），并提示用户"本步已收工可继续，也可新开会话续跑——新会话从落盘文件恢复上下文"。

## 三、路由表（每文档的必需输入 + 规则文件）

| 用户要 | 必需输入 | 规则文件 |
|---|---|---|
| ① 器件清单 | 需求文档、资源库（手册/价格库/白名单/历史 BOM） | 01-device-list.md |
| ② 框图 | 器件清单或选型定案、电源轨表、接口信号清单、板级划分 | 02-block-diagram.md |
| ③ 电源计算表 | 器件清单、各芯片手册电流值、**用户确认的额外耗流接口** | 03-power-calc.md |
| ③+ 电源树 | ③的轨表 | 03-power-calc.md（绘图部分） |
| ④ 接口定义表 | 框图信号清单、耗流数据、**pin 序排列方式（必须问）** | 04-interface.md |
| ⑤ 时序表+图 | 参与芯片清单、各芯片手册时序章节、电源时序 | 05-sequencing.md |

## 四、全局纪律（每一步都适用，违反=返工）

1. **数值三源，绝不估算**。表格/图/文档里的每个数值只能来自：①芯片手册（记章节表号）；②设计指南/参考设计文档；③用户确认记录。三者都不占 → 标"待确认/待打合"并列入向用户/厂商的确认清单。手册只有 typ 没有 max → 填 typ 并注明"max 手册缺"，不许拿 typ 放大充当 max。手册测试条件与本项目工况不同 → 标注口径差异按上界保守取。历史估算值进正式表格前必须溯源，溯源不到就降级为待确认项。为什么：估算值一旦进表就会变成"伪事实"被后续轮次反复引用，溯源成本远高于当初留空。
2. **确认前置，一次问全**。每个文档开跑前，把该文档所有需要用户拍板的项一次性列全先问（路由表加粗项都是必问项）。运行过程中遇到任何不明确的需求——包括"存在多种理解方式""有多种可选方案""参数无处可查"——都必须停下来向用户确认，列出选项，绝不默默选一个。宁可多问一轮，不做返工。
3. **改一步验一步**。批量修复/调整必须小步执行小步验证，禁止一轮大改直接交付。每轮修改后重跑全部相关检测确认没有引入新问题。为什么：一次改几十处时，一处坐标联动遗漏会产生连锁新问题（实际教训：一轮升字号引发 6 处新干涉）。
4. **交付前三道闸**（尤其 drawio 图）：
   - 几何检测全绿（scripts/checks/ 工具链，用法见 02-block-diagram.md）；
   - 目视复核（PNG 裁剪局部放大逐区检查，不看不看全图缩略）；
   - 语义级审计（连接器行配对表、线-字双向配对、与上一版 diff）。
   为什么：几何全绿 ≠ 图是对的——行错位、标签错挂、误删线这类语义缺陷几何检测结构性看不见。
5. **范围严格按用户口径**。清单/表格只做用户要求的范围，不自行扩展（框图要画 ≠ 清单要列）；用户口头定案与文档现状冲突时以口头定案为准。发现无关问题提及但不顺手改。
6. **用中文回复；Excel 全术语跟用户口径**（例：用"总线"不用"母线"），全文统一。
7. **MCP 优先，探完才许放弃**。必需输入优先通过 MCP（hdb_* 工具）取证；任何"MCP 取不到"的判定必须先用该工具的**显式最大参数**探过、必要时降维成点清单逐条探、跨时间窗重试 ≥2 次，才允许降级本地副本，降级必须登记探边记录。"成本高/输出吵" ≠ "不可行"。逐工具探法与缺陷快照见 references/mcp-probe.md。为什么：AAA 实测复盘显示，此前"30% 只能走本地"里七成是把默认参数/单次失败误判成工具极限（教训：max_chunks=20 读出封面就说 chunking 拿不到正文；一次 429 就整场弃用 RAG）。

## 五、references 使用指引

- **workflow.md**：全流程模式必读。五步详解、子代理分工、断点续传机制、五个必含确认项。
- **signal-chain.md**：读手册下任何链路/功能结论前必读。三段验证法、排除性结论硬规则——本项目最大的返工源（一次链路误判导致下游一整串结论作废）。
- **table-style.md**：任何 xlsx 产出前读。深蓝表头斑马纹版式、openpyxl 行列自适应、公式链要求。
- **mcp-probe.md**：任何交付物取数前扫一眼（2026-11 起生效）。MCP 优先 + 探边后才许放弃、逐工具探法与缺陷快照、降级登记模板——它管"MCP 路径穷尽没"，和"数值三源"配套。
- **01~06 专项文件**：做对应文档时读，内含该文档的全部规则、格式定稿、机制坑与自检清单。

## 六、scripts 使用指引

- `scripts/checks/`：drawio 检测工具链（scan_issues.py 几何七项、_tcheck.py 文字-连线、_collision.py 线-块、_xcheck.py 跳弧、scan_text_block.py 文字-文字/块、_audit.py 孤儿/缺标注/幽灵三向）。用法与豁免规则见 02-block-diagram.md 第 7 节。
- `scripts/templates/`：各文档生成脚本的架构参考模板——都是数据驱动架构（块注册表/行注册表是唯一数据源，改数据不重写逻辑）。为新项目写生成脚本时按此架构组织，把其中的项目数据换成新项目的。逐脚本用途见 scripts/templates/README.md。
- 检测脚本是针对 mxGraph/drawio XML 的通用几何分析器，可直接对任何 drawio 文件运行；运行方式与命名机制见 02-block-diagram.md。
