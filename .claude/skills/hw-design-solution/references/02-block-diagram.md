# ② 整体硬件方案框图（drawio + PNG）

程序化生成 drawio 系统框图/电源树图的全部规则。每条都来自实际翻车教训，按"生成一份新图"的流程组织。自检工具链用法见文末第 7 节。

## 1. 定图型与布局

图类型决定流向：

- **电源树图**：顺着电流路径从上往下全垂直。输入链也要垂直（入口→防护→滤波→防反→总线→一级电源竖排页面中央）；下级/跨板模块对齐源块正下方（中心 x=源中心），跨板连线纯垂直零横移；多分支共用干竖线+短横分叉。一级电源输出直接用连线连到二级电源及负载，不画汇流条块；分级图拆 L1 总览（轨级）/L2、L3 板级（芯片级）三张。
- **系统框图**：左右式布局（对手件→本板→下级板，左→右），布局总纲 = PCB 布局理念四条：①最左侧=对外接插件（信号/供电由此引出）；②接插件右侧一列=电源芯片（纵排：输入链在列顶，二级轨沿列向下）；③板中心=SOC/MCU 主控；④主控四周均匀分布与其通信的外设，外设块统一尺寸。

模块位置先想连线：按逻辑关系排布使连线最短最直——接口芯片贴接插件、桥接芯片贴板对板条、主控居中让供电线垂直短入。布局间距调不好时优先挪块填缝（走廊每条线占 30~60px，线间≥15、距块≥19），走廊容量不够先算再画。

垂直入口链豁免：电源芯片自身（入口链 π滤波→防反→buck）属于"从上往下"不受"左入右出"约束；其余模块电源一律左输入、输出右出。

## 2. 数据驱动生成（架构铁律）

- **严禁手写绝对坐标**：块注册表 `B(name, x, y, w, h)` 是唯一坐标来源；连线端点一律 `P(name, side, pos)` 引用解析（side=L/R/T/B，pos=沿边绝对坐标，None=中点）；线标签挂所属线第 seg 段中点+偏移（随线自动跟随）；zone 文字挂 zone 相对定位。挪块时端点/标签自动跟随，联动错误从机制上消失。两端显式 pos 对齐，避免中点不齐产生斜线。
- **mxCell 输出顺序三层（z-order）**：zone 底色块（最底）→ edge 连线（中）→ 节点/文字（顶层）。先 nodes 后 edges 会让连线压在文字上。母线/连接器条做 under 层（zone 后、edges 前），允许信号线穿越。
- **根 cell 必须** `<mxCell id="0"/><mxCell id="1" parent="0"/>` ——写成 parent="1"（layer 自引用）XML 合法但导出必崩 UnknownVizError，且无指向性报错。
- **value 属性转义必须** `html.escape(s, quote=True)` ——value 内 HTML 含双引号，quote=False 会截断 value 属性致 XML 失效。
- **连线画法**：source/target + 锚点（exitX/exitY/entryX/entryY）+ `<Array as="points">` 手工给全部拐点（不让 mxGraph 自动路由贴边）；同进出一个框的多条线锚点必须错开；平行线间距≥15px、线与块边≥10px。
- **批量改既有 drawio**：ElementTree 按 id 映射表改 mxGeometry/mxPoint 后保序写回（drawio 正常渲染，z-order 天然保持）。动手前先确认文件当前坐标系（文件被平移过则映射表用旧坐标会全线错位）。

## 3. 供电表达：断线画法（本方法论的核心画法）

电源到用电器不再长走线（长线横穿全图造成视觉混乱），改为"短段+箭头+悬空"断线标注：

- **电源端段（段A）**：从电源输出缘引 ~60px 短段，箭头沿电流方向向外（悬空端）。
- **用电器端段（段B）**：悬空端起（无箭头），另一端箭头接触模块外沿，表明该电压输入此模块。
- **跨板**：连接器左侧段（左悬空、右箭头触连接器）+ 连接器右侧段（左接连接器、右箭头悬空）+ 对面板模块端段。
- **每段旁标电压名**（=网络名，与轨块内名称一致）——电压名是断线两端配对的唯一依据，必须标。段距 <400px 可只标一侧，远距断线对（>400px 或中间隔块群/板区）两侧都标。
- **同 net 多消费者**：同轨多路同名输出必须区分命名（如 5V_CAN1/5V_CAN2），否则断线两端无法配对。
- **保留实体连线三类**：①主电源入口链（接插件→防护→防反→一级 buck）；②一级电源→二级轨→轨分支的电源内部分配；③全部信号线。
- **紧凑断口对**（断口<40px 同排）禁止："段A箭头指断口+段B箭头入块"的双箭头观感不行——正解：合并为单段段B（与源侧段A构成远距断线对），或源与目标同侧近距时直接一根实体线。
- **线-线 T 分叉不画箭头**（分叉点本身表达流向，画了形成"指向电源"的错误观感）；块-块连线必须画箭头。
- **多段折线只在最后一段带箭头**，中间段一律 endArrow=none——转了好几个弯的连线每段都画箭头会被读成多条信号；箭头只出现在接触目标块的那一段。
- **跨板线一律两段式经连接器**：源块→连接器左/下缘（箭头指向连接器），连接器右/上缘→目标块；连接器条内不画线；同一信号连接器两侧端点必须同一水平线，且跨板线 y 必须落在连接器块 y 范围内；连接器两侧都标信号名/协议；箭头永远指向信号传播方向。绕行走廊式跨板线禁止。

## 4. 标签与文字

- **edge 标签禁止骑线**：labelBackgroundColor 白底在 PNG 导出中不可靠（不渲染）。正解=标签 offset 偏移到线旁：mxGeometry（x=沿线位置 -1~1）内加 `<mxPoint as="offset">` ——竖线标签放线右侧、横线上标签放线上方；仍挂线随动。
- **独立标注统一字号（fs25 基准）**：块内文字随块自适应（fit_lines：最宽行渲染宽 > 容器宽-2×10px 或总行高 > 容器高-2×8px 时按比例缩小，下限 12px）不参与统一。时序图等专用图字号自成基准（见 05-sequencing.md）。
- **标签双来源字号坑**：drawio 标签字号有两个来源——style 的 `fontsize=`（新建标签）与 value 内 `<font style="font-size:...">`（旧标签）。抄模板前先确认目标 cell 的字号真的在 style 里；检测脚本两者都要抓（先抓 font-size 再剥 HTML 标签，顺序反了永远抓不到）。
- **短连线（<40px）不放 edge 标签**（必然压两侧块）——改写进块内文字。
- **拥挤区标签合法摆位**：段起点左侧同排；夹在两平行线之间的标签移到线外侧；放不下用简称，再放不下写入块内文字。标签选新位置前先查该位置已有标签（文字-文字重叠靠检测+预查）。
- **text 标签的 x/y 是框左上角**、文字以框中心对齐——微调"中心左移 N"要 x=原值-N，直接把目标中心当 x 会偏一个半框宽。
- **白底标签不得骑分区色块边界**；块内文本禁止意外折行（估算字宽偏小、实际渲染更宽，临界行拆受控两行）。

## 5. 架构真实性

- 按实际架构画，不上内部信息：有负载开关画开关模块、开关画在它实际所在的板；工程内部信息（POK、待打合字样）不上图，只留表格表尾。
- 框图每模块必须有电源入线（含跨板供电）——画完后逐模块对电源架构文档的逐轨负载表核对供电域。同轨多分支共用干线段（多条 edge 前段坐标重合=视觉一条干线多点分叉）。
- 块内文字分级：主控类芯片（SOC/MCU/DSP 这类控制芯片）=名称+型号+简要特性；其余模块一律只有两行：模块名称+型号——供电轨标注、接口标注都不放块内（被删行里承担跨板线标注的，改挂到线段上）。
- OSC/NTC/GND 等小器件不上图（晶振、板级测温小件、接地符号）；芯片级功能模块（看门狗等）保留。
- 图上不放时序/汇总/核校等补充信息行——图只表达关系，其余信息全留表格。
- 存储总线这类隐含连接也要画（DDR/SDIO）。

## 6. 交付：drawio + PNG 双件

- **双交付缺一不可**：drawio（可编辑）+ 同名 PNG（直接可看）。
- **drawio CLI 导出（四个坑）**：
  ①严禁 PowerShell 管道调用（`| Out-Null` 等待 Electron 挂死）——用 `Start-Process -FilePath draw.io.exe -ArgumentList ... -PassThru -Wait` 拿退出码，参数带 `--no-sandbox --disable-gpu`（GPU 渲染崩同样报 UnknownVizError）；
  ②大图视口截断：CLI PNG 路径有固定渲染视口（~3050 物理px 高），内容超高部分不渲染。内容高×scale ≤3050 时 scale1 导出+PIL LANCZOS 整图放大交付；超高走 PDF 中转（`-x -f pdf --crop` → PyMuPDF 栅格化）；
  ③导出竞态：后台残留 drawio 实例时 CLI 立即返回、渲染继续数秒——导出前 Stop-Process 清残留，导出后核对 PNG 时间戳/大小确实更新，PIL 自查必须在此之后；
  ④CLI 导出必须绝对路径（相对路径静默失败不报错不覆盖旧 PNG）。
- **画布边框对称**：白色背景框（最大元素）决定 bbox——收底/收边时背景框同步加高，板框距画布边缘对称各 ~100。
- **PNG 裁剪自查坐标系**：PNG x = drawio x - 画布左缘偏移（先裁一条已知块核对偏移方向），裁剪区错位会把标签裁出画布。

## 7. 自检工具链（`scripts/checks/`，交付前三道闸的第一道）

对生成完的 .drawio 运行（文件路径作命令行参数），全部输出应为空或仅剩白名单项：

| 脚本 | 查什么 |
|---|---|
| scan_issues.py | 斜线（相邻路径点 dx·dy≠0）、板框重合（线沿 zone 边共线）、块缘平行贴行、端点贴角、字号审计（独立标签非基准字号）、紧凑断口对 |
| _tcheck.py | 文字-连线干涉、文字跨框（标签 bbox 与块/板框部分相交且中心不在块内） |
| _collision.py | 线穿块/贴块/悬空端点/间距<20/线贴块（平行<19px 且并行>30px）/跨板线未经连接器 |
| _xcheck.py | 线交叉双方无 jumpStyle（黑信号线全加 jumpStyle=arc，红线不加避免双弧；7px 粗线 jumpSize=10） |
| scan_text_block.py | 文字-文字重叠/间隙<8px、块伸出 zone 边、块内文字居中 |
| _audit.py | 三向语义审计：孤儿标签（无对应线）、缺标注线（有芯无线旁字）、幽灵线（全线 60px 内无文字）——距离判定统一用标签 bbox 边缘（中心点距离在 fs25 下系统性偏大） |

使用纪律：

- 检测报告先甄别再修——悬空端点三类合法情形（T 分叉/历史遗留/对外连接器引出）、on_boundary 的"接缘实体"（宽高都>1000 的 zone 才排除，连接器条 100×2150 是合法接线缘）、_tcheck 的块内文字豁免（中心在实体块内；zone 大框用"整体包含才豁免"，骑缘即报）。
- 检测器大量假报 = 事实失效——修检测器先于修图，假报修干净真问题才浮出来。
- 白名单要带注释写明原因。
- 写新检测脚本必查三条：mxPoint 解析捕获 as 属性（`(\w+)="([^"]*)"` 后按 as 分桶 poly=src+wps+tgt——数值正则丢 as 属性会假报一片）、字号双来源、距离统一 bbox 边缘。

第二道闸目视：PIL 裁剪局部放大逐区检查（缩略图看不出穿字）。第三道闸语义审计（几何全绿≠图对）：①连接器行配对表（端点落连接器左右缘的边按 y 配对，错位即报）；②线-字双向配对（每个电压标签到最近红线距离、每根红线段旁有无标注）；③与上一版备份 diff 出被删/被改的边逐条核对语义（误删线、标签错挂只有配对+备份能定案）。孤儿标签指向丢失的线=补线不是删标签；删任何标注前先跑审计。

## 8. 挪块/改线纪律（机制级）

- **挪块必须全量联动**，联动清单：块缘锚点、沿线标签、分叉从线、连接器两侧同 y 的另一段、zone 边缘关系。改线脚本尾部必须跑"标签到最近线距离"审计。
- **全量重排的连线改写必须"清空重建 waypoint"**——部分修改必留残留旧 wp 产生斜线；重排后必查孤立标签与漏改线（列出全部供电线 source/target/style 逐条核对语义）。
- **改道前先审原路径为何成立**——不必要联动→穿块→绕行掩盖→撞缘，一错连环；绕行取缝隙中分线（两侧各≥40px），禁止刚躲开一侧就定线。
- L 形连线的拐点行程被障碍夹死时（<60px）调点无解，必须挪块把区间撑开。
- **扩块/挪线一轮的连带复核**：块尺寸一变，块内文字重心、周边线行距、跨过的横线、标签摆位全要复检。
- **轨块高度不够放段A标签时**按"50px×该轨用户数"加高（间距 20 时标签上下必叠线）。
- **竖排段名坑**：drawio text 无 horizontal=0 时窄框里的多字文案按横排溢出渲染压邻列文字——正解=横排放色带左上角内侧，不用竖排。
- **drawio text value 二次 HTML 解析坑**：value 里 `&lt;` 被 drawio 还原成 `<` 后再次按 HTML 渲染，`<t1...>` 之类被当非法 HTML 标签整段吞掉——文案含不等式时避开 `<x` 模式（改写 ≤/冒号句式）。

## 9. 生成脚本模板

`scripts/templates/gen_block_diagram.py` 是数据驱动架构的完整参考（块注册表+端点引用解析+三层输出顺序+fit_lines）。新项目框图：复制该架构，替换块注册表与连线定义数据；坐标布局按第 1 节四条理论重新推导。
