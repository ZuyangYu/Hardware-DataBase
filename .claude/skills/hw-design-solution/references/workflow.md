# 全流程总控（workflow）

五步硬件方案方法论的运行总控：五步与产出物映射、模式 A/B 操作流程、子代理分工、断点续传机制、"确认前置一次问全"清单、交付前三道闸落点、⑦ 汇总的收口规则。全流程模式（模式 B）开跑前必读本文；单文档模式在核对输入与确认项时同样回到本文第五、六节。

## 一、五步与产出物映射

七项产出物按依赖关系排成执行序列。并行关系来自 SKILL.md 第一节依赖关系："①→②→④；③依赖①与②可并行；③+、⑤、⑥在各目前序完成后执行；⑦最后。"

| 步 | 产出物 | 形态 | 必需输入（详见 SKILL.md 第三节路由表） | 依赖与并行 |
|---|---|---|---|---|
| 一 | ① 关键器件清单 | xlsx | 需求文档、资源库（手册/价格库/白名单/历史 BOM） | 起点，其余全部前置 |
| 二 | ② 整体硬件方案框图 | drawio + PNG | ①（或选型定案）、电源轨表、接口信号清单、板级划分 | 依赖 ① |
| 三 | ③ 电源计算表 | xlsx | ①、各芯片手册电流值、**用户确认的额外耗流接口** | 只依赖 ①——① 收工后与 ② **可并行**（③ 必须排在 ① 之后） |
| 三 | ③+ 电源树（L1/L2/L3） | drawio + PNG | ③ 的轨表 | 跟随 ③，紧随其后 |
| 四 | ④ 接口定义表 | xlsx | ② 的信号清单、③ 的耗流、**pin 序排列方式（必须问）** | 汇合点：依赖 ②（信号）与 ③（耗流）；链路 ①→②→④ |
| 五 | ⑤ 上下电时序表 + 时序图 | xlsx + drawio/PNG | 参与芯片清单、各芯片手册时序章节、电源时序（③ 的轨序约束） | 依赖 ③；与 ⑥ **可并行** |
| 五 | ⑥ 热风险分析表 | xlsx（全公式链） | ③ 的功耗、**Ta 出处（查需求，勿惯例假设）**、各芯片手册热阻 | 依赖 ③；与 ⑤ **可并行** |
| 收尾 | ⑦ 硬件方案汇总 | md | 以上全部定案 | 最后收口，规则见本文第七节 |

并行口诀：**②③ 并行**（③ 只吃 ①）、**④ 汇合 ②③**、**⑤⑥ 并行吃 ③**、**⑦ 收口**。

## 二、模式 A：单文档执行

用户点名一个文档（"生成框图""出接口表""做个热分析"）——最常见模式。动作序列：

1. **对路由表**：打开 SKILL.md 第三节路由表，定位该文档的必需输入与规则文件；
2. **核输入**：从项目目录已有的定案文件（xlsx/drawio/md）里核对必需输入齐不齐——不看现有文件就开跑等于凭记忆续跑，禁止（见第四节）；
3. **读规则**：输入齐全 → 读完对应 reference（涉及信号链结论先读 signal-chain.md；xlsx 产出先读 table-style.md）；
4. **问确认**：按本文第五节清单，把该文档所有需要用户拍板的项一次问全（含路由表加粗项）；
5. **执行**：按对应 reference 的规则生成；
6. **验与闸**：改一步验一步，小步执行小步验证；交付前过三道闸（第六节）；
7. **落盘**：定案即时写入产出物文件，收工提示（第四节）。

输入缺失 → 明确告诉用户缺什么：要么用户提供，要么确认是否需要先跑前置文档。**不要在输入不齐时凭猜测开跑**。

## 三、模式 B：全流程与子代理分工

用户给需求文档要整套方案：按第一节依赖序推进，**每完成一个文档交给用户确认，确认通过才进下一个**。

### 子代理分工

| 事项 | 谁做 | 说明 |
|---|---|---|
| ② 框图的生成+自检循环 | 子代理（整体交付） | 全流程中修复迭代最重的环节：drawio 生成 → scripts/checks 检测 → 修 → 再检 → PNG 导出，整条循环交给子代理跑完再回来；主会话只做确认与决策分发 |
| 表格类生成（①③④⑤⑥ 的 xlsx） | 可交子代理 | 主会话把数据（清单行、轨表、耗流、确认结果）备齐后，整体交给子代理生成与自检 |
| 确认分发 | 主会话 | 确认前置一次问全；过程中遇到任何不明确处停下来问用户、列选项，绝不默默选一个 |
| 定案落盘 | 主会话 | 每个文档收工时核对所有定案已写入产出物文件 |
| 防崩纪律 | 主会话 | 改一步验一步、三道闸收口、断点续传（第四节） |

分工原则：**机械性生成与自检循环交给子代理；确认、决策、落盘留在主会话。**

## 四、断点续传机制

- **定案即时落盘**：每个文档收工时，所有定案必须已是文件形式（xlsx/drawio/md）——数据在表里、待确认/待打合项在表尾备注，不留在会话记忆里；
- **收工提示**：每步收工提示用户"本步已收工可继续，也可新开会话续跑——新会话从落盘文件恢复上下文"；
- **新会话恢复流程**：先读已落盘产出物 → 再读 SKILL.md 路由表判断进行到哪一步 → 从缺输入的那一步继续。**禁止凭记忆续跑**——新会话里上一个会话的记忆不存在，唯一可信上下文是落盘文件与 SKILL.md；
- **待办交接面**：各文档表尾的"待打合"清单就是跨会话待办，新会话恢复后先扫一遍各表尾，把未决项纳入下一步的确认问题。

## 五、"确认前置一次问全"清单

每个文档开跑前，把该文档所有需要用户拍板的项**一次性列全先问**；运行中遇到"存在多种理解方式""有多种可选方案""参数无处可查"，同样停下来列选项问，绝不默默选一个（SKILL.md 第四节纪律 2：宁可多问一轮，不做返工）。五个文档的必含确认项汇总：

| 文档 | 必含确认项 | 出处 |
|---|---|---|
| ② 框图 | 图型与布局确认：系统框图/电源树各按哪套图型（左右式 / 全垂直）、板级划分、布局走向按 PCB 布局四条 | 02-block-diagram.md 第 1 节 |
| ③ 电源计算表 | 除已列芯片外是否还有耗流较大的硬件接口（逐项确认：电压多少、电流多少、来自哪条轨） | 03-power-calc.md 第二节；SKILL.md 路由表加粗项 |
| ④ 接口定义表 | pin 序排布方式：上排 1~N → 下排 N+1~2N（上下正对），还是奇偶交叉——连接器厂家间不一致，必须显式确认，不可默认 | 04-interface.md 第一节；SKILL.md 路由表加粗项 |
| ⑤ 时序 | 上电顺序、轨间延迟来源（手册推荐值 vs 实测）、下电是否逆序 | 05-sequencing.md 第二节〔⑤ 确认项为初稿推断，待 owner 校订〕 |
| ⑥ 热风险表 | Ta 出处：手册工况 / 项目环境 / 客规——禁止惯例假设 | SKILL.md 路由表 ⑥ 行加粗项；06-thermal.md 第二节 |

① 器件清单无独立必问项：选型判据按 01 的三代规则（v2 比价顺序 / v3 已量产≠最优 / v4 历史实证≠资源匹配）执行，过程中不明确处按本节通用规则停下来问。

## 六、交付前三道闸的落点

每个文档交付前过三道闸，全过才收工：

| 闸 | 查什么 | 出处纪律 | 落点 |
|---|---|---|---|
| 第一道：几何检测全绿 | drawio 类产出跑 scripts/checks 工具链全绿（白名单除外）+ PIL 裁剪局部放大目视复核 + 语义级审计（连接器行配对表、线-字双向配对、与上一版 diff）——几何全绿 ≠ 图是对的 | SKILL.md 第四节纪律 4；02 第 7 节 | ② 框图、③+ 电源树、⑤ 时序图 |
| 第二道：数值三源齐全 | 表内每个数值可溯源到三源之一：①芯片手册（记章节表号）②设计指南/参考设计文档 ③用户确认记录；三者都不占 → 标"待确认/待打合"列入确认清单，绝不估算 | SKILL.md 第四节纪律 1；03 第一节 | ①③④⑤⑥ 全部 xlsx；⑦ 汇总引用的数值同样逐个溯源 |
| 第三道：范围与用户口径一致 | 只做用户要求的范围不自行扩展（框图要画 ≠ 清单要列）；Excel 全术语跟用户口径全文统一；用户口头定案与文档现状冲突时以口头定案为准 | SKILL.md 第四节纪律 5、6 | 每步收工前自查；⑦ 汇总定稿前整册过一遍 |

## 七、⑦ 硬件方案汇总（收尾文档）

路由表承诺：⑦ 汇总方案书的规则文件即本节（"workflow.md 末节"）。汇总 = 把 ①~⑥ 的定案汇编成一份 md 方案书。

- **形态**：md 单册；输入 = 以上全部定案文件；
- **必含内容**：
  1. 需求与口径回顾：用户拍板记录（确认项结论、免计项、范围口径）；
  2. 关键器件选型结论——每个主芯片标注"历史验证 / 新选型"（01 第一节：状态标注写在汇总文档里，不在清单加列）；
  3. 框图与电源树：引用 PNG，注明文件名与版本；
  4. 电源架构结论：轨表 + 校验逻辑"电源输出电流能力 > 负载最大耗流"（03 第一节）；
  5. 接口定义要点：pin 序排位与正对关系、差分/隔离布局说明、过流依据（04 第五节表尾内容上收）；
  6. 上下电时序结论：时序表 + 时序图 + 轨间延迟依据（05）；
  7. 热风险结论：✓/临界/超规分级结果与临界、超规芯片清单（06）；
  8. **待打合清单集中汇总**：从各文档表尾收拢，逐项列"事项 / 当前状态 / 需谁确认"；
- **范围纪律**：汇总只汇编定案，不引入新数值——发现缺口回填到对应专项文档再引用；引用数值照第二道闸逐个溯源。
