# ① 关键器件清单

## 一、选型逻辑（三代演进，全部生效）

**v2 比价顺序**：技术指标达标 → 供应商质量 → 方案总体成本。SOC 与 MCU 作为组合平权比价（不是只比 SOC 单颗）。价格库的质量备注是质量否决依据（实例：某桥接芯片价格最低但备注"质量审核不通过"→ 直接剔除）。

**v3 已量产 ≠ 最优**：技术达标前提下，有更便宜且公司确认可使用的物料就应选用。价格库有价 = 公司认可物料池的信号。历史实证是质量证据之一而非最高优先级。

**v4 历史实证 ≠ 资源匹配（针对 MCU/资源类器件）**：历史项目用过 ≠ 本项目够用——必须逐接口核对本项目需求：GPIO/SPI/IIC/CAN/ADC 各需几路、pin 预算、封装 SKU 资源。历史实证只证明"芯片能用"，不证明"这个封装/这个 SKU 够用"（实例：MCU 的 CANFD 是随 SKU feature 位的可选外设，64pin 是否含该位必须查官方 Orderable Part Number 表——此类核对曾补出两个关键风险）。

**配套硬证据**：

- 历史项目 BOM 的 ERP 编码与价格库编码对照 = "历史验证"的硬证据（价格库条目多从历史项目采购记录沉淀）；
- 大众白名单等客户约束先过滤（CAN/ETH 类芯片常限白名单，ESD/CMC 也须同源选）；
- 芯片手册信号链结论见 signal-chain.md（选型判据与链路分析互为输入）。

## 二、清单格式（定稿，不再自加列）

**列结构（仅 5 列）**：序号 | 器件（类别描述，如"DC-DC buck""SOC 主处理器"） | 型号（纯型号，无封装/参数括号） | 厂家 | 单机用量（"×N"文本）。

**范围（只列主芯片级）**：SOC/MCU/存储/接口/显示链路芯片 + 电源转换芯片（buck/LDO/PMIC）。

**不列的小器件（永久生效）**：负载开关等开关类、防反二极管、复位 IC、晶振、NTC、防护小件（TVS/ESD/CMC/π滤波）、连接器、DMD 插座、灯板、结构料——框图才画连接关系，清单只保留主芯片。开关/二极管/复位 IC 这类外围小料即使型号待询价也不列。

**结构规则**：不分板分组、无说明行、无备注列、无验证状态列；器件/型号列不写括号说明；同型号芯片合并一行计总量；排序：电源在前 → 主芯片 → 接口 → 显示链路。

**选型状态标注**：每个主芯片区分"历史验证"（历史项目 BOM 同编码）与"新选型"——写在汇总文档里，不在清单加列。
